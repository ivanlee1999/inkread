InkRead 0.16.23 improves article sources and reading progress while preserving existing accounts, saved articles, annotations and subscription settings.

- Public Verge articles retain editorial endings, images and retailer links instead of losing them during generic extraction.
- Public New Yorker articles no longer mistake editorial metering classes for an active access barrier. Visible summaries, images, citations and paragraph order are retained. Declared subscriber restrictions, sign-in/subscription prompts, browser challenges and explicit paywall flags remain blocked; publisher scripts are not executed.
- Article Source remembers Local full text, Server content or Original RSS separately for each subscription. Existing presets keep their prior behavior until a source is explicitly chosen. Original RSS uses an anonymous, bounded request to the subscribed feed and an exact article-link match, with a separate cache. If the article has left the feed window, useful current text stays available. Newsletter/privacy controls remain in force.
- Continued next/previous reading updates the newspaper list to the current article across page boundaries. Later manual list navigation supersedes pending reader progress.

Server content can still be a feed summary; refreshing an existing server item does not itself trigger server extraction. The large New Yorker Best Books catalogue exceeds Android's unchanged 2 MiB download/interpreter budgets and continues to require browser fallback. No access restriction is bypassed.

The existing application ID (`me.ash.reader`) and signing identity are retained. An additive Room 8-to-9 migration adds only the nullable per-subscription display mode; existing preferences and article identities are preserved.

Validation includes parser/source-quality and source-mode/navigation regressions, actual SQLite migration checks, and 15 Android 11 ARM64 runtime cases covering Room persistence, parser limits, reader/list controls, saved public publisher responses and minified parser execution. The runtime fixtures used an isolated application ID and temporary verification signing key; those APKs are not release assets. Physical handset/e-ink/mouse behavior and live authenticated account acceptance remain device checks.
